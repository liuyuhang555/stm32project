# STM32F103C8T6 FreeRTOS 多任务协作物联网系统

> 
> 基于 STM32F103C8T6 + FreeRTOS 的多任务协作与系统可靠性设计实战项目，嵌入式学习、秋招简历项目。

## 硬件平台

- MCU：STM32F103C8T6（**标准库开发**）
- 外设：DHT11 温湿度传感器、0.96 寸 I2C‑OLED、独立按键、板载 LED、ESP8266‑01 AT WiFi 模块
- 开发环境：Keil MDK‑ARM

## 引脚定义

- LED：PC13
- KEY1：PA13
- KEY2：PA12
- DHT11：PB14
- OLED I2C：PB7(SDA)，PB6(SCL)
- USART1(ESP8266‑AT)：PA9(TX)，PA10(RX)
- USART2 (调试串口)：PA2 (TX)，PA3 (RX)

## ✅功能实现

### 外设驱动层

1. **DHT11 温湿度采集**，增加传感器故障统计、采集异常计数，采集失败标记上报
2. **0.96 寸 I2C‑OLED 屏幕**：实时刷新温湿度、故障数量、报警阈值、报警状态；多任务共享显示资源，使用互斥锁解决多任务抢占造成的乱屏问题
3. **按键交互**：短按修改温湿度上下报警阈值；长按触发看门狗复位，模拟任务卡死故障
4. **片内 Flash 参数存储**：报警阈值写入 Flash，掉电数据不丢失，上电自动加载保存参数
5. **IWDG 独立看门狗 + 任务心跳机制**：每个业务任务定期输出心跳标志；心跳超时判定任务卡死，触发硬件复位，实现故障自愈，提升整机可靠性

### FreeRTOS 内核与多任务设计

> 
> 采用**模块化任务拆分 + 消息通信**，尽量避免裸机全局共享变量，实现任务解耦

#### 任务划分

1. **SensorTask（传感器采集任务）**
周期性读取 DHT11 温湿度，采集完成后封装数据送入消息队列，触发采集完成事件；统计传感器故障次数。
2. **DisplayTask（OLED 显示任务）**
等待队列收到温湿度数据，获取 OLED 互斥锁后刷新屏幕；无新数据时任务休眠，降低 CPU 占用。
3. **WatchdogTask（看门狗监控任务）**
系统健康巡检，收集各个业务任务心跳标志；心跳超时判定任务卡死，触发 IWDG 看门狗复位。
4. **UploadTask（MQTT 上云任务，ESP8266‑AT）**
WiFi 自动重连，MQTT 周期性上报传感器数据至 OneNET 云平台；规避老版 ESP‑01 固件`SEND OK`应答丢失导致反复重启的 bug，仅校验`>`提示符判定发送完成，云端可稳定接收数据。调试打印做取舍，关闭冗余串口输出，避免刷屏引发堆栈溢出复位。
5. **LowpowerTask（低功耗待机任务，预留迭代）**
系统空闲时进入 Stop 低功耗模式；已定位 USART 时钟关闭造成串口打印卡死问题，等待移除阻塞式串口打印后重新调试验证。

#### 数据流向

```
DHT11采集 → SensorTask → 消息队列+事件组 → DisplayTask（OLED本地显示）
                                      ↘ UploadTask（ESP8266 MQTT上云→OneNET云端）
按键输入 → 修改阈值参数 → Flash保存
所有任务 → 心跳标志 → WatchdogTask → IWDG看门狗故障复位
OLED资源多任务争抢 → 互斥锁（解决屏幕乱码、花屏）
```

> 
> 通信机制总结：

- **队列 Queue**：传递温湿度结构体数据，生产者 / 消费者模型
- **事件组 EventGroup**：同步采集完成、报警触发事件
- **互斥锁 Mutex**：保护 OLED 公共显示资源，学习优先级翻转与优先级继承原理
- **任务栈水位监测**：`uxTaskGetStackHighWaterMark()`监控剩余栈空间，开启 FreeRTOS 栈溢出检测，提前规避栈越界死机

### 联网模块现状

- ESP8266‑AT 驱动完整保留，WiFi 连接稳定，MQTT 成功对接 OneNET 平台，云端可接收周期性温湿度数据；
- 解决痛点：ESP 老固件`MQTTPUBRAW`偶尔丢失`SEND OK`应答，放弃等待该应答，仅校验`>`提示符判定发送完成，消除模块反复重启故障；
- UploadTask 支持条件编译屏蔽，调试阶段可关闭 WiFi 大量重连日志，减少串口负载。

## 工程说明

1. UploadTask 支持条件编译屏蔽，关闭 WiFi 冗余调试打印，防止串口刷屏引发堆栈溢出复位；
2. 栈水位、任务状态打印属于调试代码，正式发布版本可注释关闭；
3. 驱动分层：外设底层驱动、FreeRTOS 业务任务、AT 通信驱动分离，便于移植和迭代；


## 📍待优化方向

1. Lowpower 低功耗模式：Stop 模式关闭 USART 时钟会造成阻塞式 printf 卡死，后续移除阻塞串口打印后重新调试验证。
2. 增加网络断线心跳探测，识别 ESP 静默掉线，主动重连 MQTT，进一步提升长连接稳定性。

## 📖核心学习要点

1. FreeRTOS 基础：任务创建、优先级调度、阻塞休眠，队列 / 事件组 / 互斥锁通信机制；
2. 多线程资源竞争问题，互斥量原理、优先级翻转与优先级继承；
3. 任务栈余量评估、栈溢出检测方法，嵌入式系统内存风险排查；
4. STM32 片内 Flash 读写，非易失性参数掉电存储方案；
5. 嵌入式可靠性设计：独立看门狗、任务心跳监控、故障自动复位自愈；
6. ESP8266‑AT 时序调试，规避 AT 固件固有 bug，物联网 MQTT 上云开发。

## 使用说明

1. 开发环境：Keil MDK‑ARM，标准库
2. 打开`Keil_Project`内工程编译下载
3. UploadTask 可通过宏开关条件编译开启 / 关闭联网功能
